<objective>
Record every LLM call made during document processing (extraction + entity resolution) in the `llm_call_log` PostgreSQL table with full prompt text, response text, token usage, cost, duration, model, and activity type — with Temporal replay safety via deterministic IDs.

Purpose: Provide the data layer for Phase 31 (API endpoint) and Phase 32 (UI viewer). Pipeline activities already call `record_llm_usage()` for the `llm_usage` table — this phase adds the same fire-and-forget pattern for the richer `llm_call_log` table that includes prompt/response text.

Output: New `llm_call_recorder.py` module, modifications to `llm.py` (add prompt_text/response_text to usage dict), modifications to 3 activity files, and modifications to 2 delete paths in `documents.py`.
</objective>

  <action>
    Create `src/eth_pipeline/llm_call_recorder.py` following the exact pattern of `llm_usage.py`:

    1. Module docstring: "Fire-and-forget LLM call log recorder for Temporal activities."
    2. Same imports: hashlib, logging, Any from typing, get_db from eth_pipeline.db
    3. `__all__ = ["record_llm_call_log"]`
    4. Function signature:

    ```python
    async def record_llm_call_log(
        db_params: dict[str, Any],
        document_id: str,
        activity_type: str,
        chunk_index: int,
        prompt_text: str,
        response_text: str,
        model: str,
        prompt_tokens: int,
        completion_tokens: int,
        total_tokens: int,
        duration_ms: int,
        cached_tokens: int | None = None,
        cost: float | None = None,
    ) -> None:
    ```

    5. **Deterministic ID**: SHA256 of `document_id:activity_type:chunk_index` (same pattern as llm_usage)
    6. **Timestamp**: `datetime.now(timezone.utc)` as ISO string
    7. **INSERT with ON CONFLICT DO UPDATE** — same UPSERT pattern for replay safety
    8. **Fire-and-forget**: Errors caught at `except Exception` and logged at WARNING — never raised
    9. **INSERT query** targeting the `llm_call_log` table with all required fields

    The llm_call_log table has these columns:
    - id TEXT PRIMARY KEY
    - prompt_text TEXT DEFAULT NULL
    - response_text TEXT DEFAULT NULL
    - prompt_tokens INTEGER DEFAULT NULL
    - completion_tokens INTEGER DEFAULT NULL
    - total_tokens INTEGER DEFAULT NULL
    - cached_tokens INTEGER DEFAULT NULL
    - cost REAL DEFAULT NULL
    - duration_ms INTEGER DEFAULT NULL
    - model TEXT DEFAULT NULL
    - activity_type TEXT DEFAULT NULL
    - document TEXT NOT NULL REFERENCES document(id) ON DELETE CASCADE
    - timestamp TIMESTAMPTZ DEFAULT NULL

    The ON CONFLICT DO UPDATE should update: prompt_text, response_text, model, prompt_tokens, completion_tokens, total_tokens, duration_ms (same fields that might differ on replay when a model returns slightly different token counts).
  </action>
