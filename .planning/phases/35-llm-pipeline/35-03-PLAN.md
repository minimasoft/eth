    ## Part B: DocumentProcessingV7Workflow class

    Add the class AFTER the existing `DocumentProcessingWorkflow` class (not inside it). Follow the EXACT structure of the existing class:

    ```python
    @workflow.defn
    class DocumentProcessingV7Workflow:
        """Orchestrate v7 document event extraction and persistence.
        
        This workflow processes a single document through the v7 pipeline:
        1. Verify schema_version == 'v7' (route v6 docs to old workflow at caller level)
        2. For each chunk (chunk_index 0..N):
           a. Read up to 10 prior events (compact context: id, title, description)
           b. extract_events_v7_activity(chunk_text, prior_events) — LLM extraction
           c. store_events_v7_activity(chunk_events) — per-chunk commit
        3. resolve_references_v7_activity — post-extraction offset computation
        4. Mark document as processed; return summary
        """
        
        @workflow.run
        async def run(self, document_id: str) -> dict:
            ...
    ```

    **The `run` method implementation order:**

    1. **Mark as processing_v7**: `await workflow.execute_activity(update_document_status_activity, args=[document_id, "processing_v7"], start_to_close_timeout=timedelta(seconds=10))`

    2. **Fetch chunks**: `chunks_result = await workflow.execute_activity(get_document_chunks_activity, args=[document_id], start_to_close_timeout=timedelta(seconds=30))`; extract `chunks = chunks_result.get("chunks", [])`

    3. **Per-chunk iteration** (the core loop):
       - Initialize `event_count = 0`
       - For `chunk_idx, chunk in enumerate(chunks)`:
         a. **Get prior events**: `prior_result = await workflow.execute_activity(get_prior_events_activity, args=[document_id], start_to_close_timeout=timedelta(seconds=10))`; extract `prior_events = prior_result.get("prior_events", [])`
         b. **Extract**: `extract_result = await workflow.execute_activity(extract_events_v7_activity, args=[document_id, chunk_idx, chunk["text"], prior_events], start_to_close_timeout=timedelta(seconds=900), retry_policy=RetryPolicy(maximum_attempts=3, initial_interval=timedelta(seconds=5), backoff_coefficient=2.0))`
         c. **Log refusal if detected**: `if extract_result.get("refused"): workflow.logger.warning("Chunk %d refused: %s", chunk_idx, extract_result.get("refusal_reason", "unknown"))`
         d. **Store**: `store_result = await workflow.execute_activity(store_events_v7_activity, args=[document_id, chunk_idx, extract_result.get("events", [])], start_to_close_timeout=timedelta(seconds=120))`; check for "error" key and raise if present
         e. **Update progress status**: `await workflow.execute_activity(update_document_status_activity, args=[document_id, f"extracting_v7_part_{chunk_idx + 1}"], start_to_close_timeout=timedelta(seconds=10))`
         f. **Accumulate count**: `event_count += store_result.get("events_stored", 0)`

    4. **Resolve references**: `resolve_result = await workflow.execute_activity(resolve_references_v7_activity, args=[document_id], start_to_close_timeout=timedelta(seconds=120))`

    5. **Mark processed**: `await workflow.execute_activity(update_document_status_activity, args=[document_id, "processed"], start_to_close_timeout=timedelta(seconds=10))`

    6. **Return summary**: `{"document_id": document_id, "event_count": event_count, "status": "processed", "refs_resolved": resolve_result.get("resolved", 0)}`

    7. **Error handler** (at the end of `run`): Same pattern as existing workflow — `except Exception as exc:` → `await workflow.execute_activity(update_document_status_activity, args=[document_id, "failed", str(exc)], ...)` → `raise`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Temporal workflow replay → Activity re-execution | On replay, activities are re-invoked with same arguments. Per-chunk commit ensures only the replayed chunk is affected. |
| Workflow orchestrator → Activity layer | The workflow passes chunk text and prior events as arguments. Temporal handles serialization. No trust boundary concern — same process. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-12 | Tampering | Temporal replay causes chunk re-extraction with different LLM output | accept | LLM responses are non-deterministic even at temperature=0. The per-chunk commit pattern IS the mitigation — on replay, the activity re-extracts and re-stores, overwriting the chunk's previous events. Cost is incurred but correctness is maintained. Accepted risk: replay produces different extraction results. |
| T-35-13 | Denial of Service | All chunks refused → document marked processed with zero events | mitigate | If every chunk returns `refused=True`, the workflow still completes with status "processed" but with event_count=0. The `test_no_refusals_on_corpus` test (Plan 35-01) should catch this before deployment. If the corpus triggers widespread refusals, the system prompt needs refinement before production use. |
| T-35-14 | Elevation of Privilege | Schema version routing bypass | accept | The caller (API endpoint) checks document.schema_version and starts the appropriate workflow. No in-workflow branching for v6 vs v7. If a v6 document is routed to the v7 workflow, it will fail because document_chunk rows may not exist. Accepted risk: caller is responsible for correct routing (this is Phase 35's design, not a bug). |
| T-35-15 | Information Disclosure | Prior events expose event data across chunks | accept | Prior events contain id, title, description, time_start — summary-level data, not full event objects. This is by design for PIP-02 (compact prior context). No PII beyond what's already in the document. Accepted risk level: low. |
</threat_model>
