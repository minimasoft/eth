    1. **Section separator header** with `-- ====== v4.0 Schema Evolution ======` using the same decorative style as the existing separators in schema.surql (two lines of dashes above and below). Include a multi-line comment block explaining this is Phase 13 additive DDL and all statements are idempotent (per D-01).

    2. **Reference offset fields** (OFFS-01, OFFS-02, OFFS-04) — Three new nullable fields on the `reference` table:
       - `page_number` TYPE int | null DEFAULT null
       - `page_offset_start` TYPE int | null DEFAULT null
       - `page_offset_end` TYPE int | null DEFAULT null
       Each with COMMENT describing its purpose and that null is for plain-text documents.
       Pattern: `DEFINE FIELD <name> ON TABLE reference TYPE int | null DEFAULT null COMMENT '...';`
       These are additive (new fields) — NO OVERWRITE keyword needed.

    3. **Event entity_type enum extension** (EVNT-01, D-09) — OVERWRITE the existing `entity_type` field:
       `DEFINE FIELD OVERWRITE entity_type ON TABLE canonical_entity TYPE string ASSERT $value INSIDE ['place', 'person', 'object', 'event'] COMMENT '...';`
       CRITICAL: Must use `OVERWRITE` keyword. Without it, SurrealDB errors because the field already exists. Update the COMMENT to mention "event added in v4.0".

    4. **event_entity_link table** (EVNT-05, D-11, D-12) — New SCHEMAFULL table with fields:
       - `event` TYPE record<event>
       - `entity` TYPE record<canonical_entity>
       - `relationship_type` TYPE string (free-form, COMMENT documents expected patterns like "involves", "located_at", "occurred_during")
       - `role` TYPE string | null DEFAULT null (free-form, COMMENT documents expected patterns like "subject", "object", "location")
       - `confidence` TYPE number | null DEFAULT null ASSERT $value IS NONE OR ($value >= 0 AND $value <= 1)
       - `notes` TYPE string | null DEFAULT null
       - `created_at` TYPE datetime DEFAULT time::now() READONLY
       Use plain SCHEMAFULL (NOT TYPE RELATION) — per D-12 this is an explicit table. Each field has its own DEFINE FIELD statement with COMMENT. The table COMMENT explains this is populated by Phase 16 and to use RELATE queries.

    5. **document_event_log table** (LOGS-01, D-03 through D-08, D-14) — New SCHEMAFULL table with fields:
       - `id` TYPE string (COMMENT documents deterministic ID pattern: SHA256 of document_id + step_name + sequence_number truncated to 16 hex chars, per D-05)
       - `document` TYPE record<document>
       - `step_name` TYPE string (free-form per D-04, COMMENT documents expected values like "extract_text", "chunk_document", etc.)
       - `severity` TYPE string ASSERT $value INSIDE ['info', 'warning', 'error'] (per D-03)
       - `message` TYPE string
       - `details` TYPE object | null FLEXIBLE DEFAULT null (per D-08 — same pattern as canonical_entity.properties)
       - `created_at` TYPE datetime DEFAULT time::now() READONLY (per D-07)
       The TABLE COMMENT must include the D-14 warning: "⚠ GraphQL mutations available but DISCOURAGED — writes should go through REST API or Temporal activities only".

    6. **Indexes** (the agent's Discretion per CONTEXT.md) — Three indexes:
       - `idx_document_event_log_document` ON TABLE document_event_log COLUMNS document — for per-document log queries by GET /documents/{id}/logs
       - `idx_event_entity_link_event` ON TABLE event_entity_link COLUMNS event — for graph traversal from event to linked entities
       - `idx_event_entity_link_entity` ON TABLE event_entity_link COLUMNS entity — for reverse graph traversal from entity to linked events

    Use the same COMMENT, indent, and formatting style as the existing schema.surql (4-space indent for continuation lines, `-- ------` subsection separators). Each DEFINE TABLE and DEFINE FIELD MUST carry a COMMENT for auto-GraphQL documentation.

    Per RESEARCH.md anti-patterns and pitfalls:
    - DO use `OVERWRITE` on entity_type (Pitfall 1 → error without it)
    - DO use `TYPE object | null FLEXIBLE DEFAULT null` for details (Pitfall 2 → SurrealDB v3.0 rejects undefined fields without FLEXIBLE)

    - No TTL or auto-cleanup on document_event_log (D-06 — deferred to future milestone)
    - Existing scripts/init_schema.py unchanged (D-02)
