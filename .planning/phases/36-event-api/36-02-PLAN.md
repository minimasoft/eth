## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-01 | Tampering | `list_events_v2` sort param | mitigate | Whitelist `allowed_sorts = {"time_start", "time_end", "created_at", "title"}` — user-supplied `sort` value defaults to `"time_start"` if absent from set. ORDER BY clause uses ONLY whitelisted column name via f-string interpolation on `sort_col` (not raw `sort`). |
| T-36-02 | Tampering | `list_events_v2` search param / `get_event_v2_detail` event_id | mitigate | All VALUES use asyncpg `$N` parameterized placeholders: `f"%{search}%"` goes into `$1` as bound string, NOT string-interpolated. `event_id` goes into `$1` as bound string in WHERE. SQL injection not possible — parameterization is at the protocol level. |
| T-36-03 | Denial of Service | `list_events_v2` per_page | mitigate | `per_page: int = Query(20, ge=1, le=100)` — hard cap at 100 prevents resource exhaustion via oversized pages. |
| T-36-04 | Information Disclosure | All endpoints — DB exceptions | mitigate | All `except Exception` blocks return generic `HTTPException(502, "Failed to query database.")` with `logger.error(...)` internally. No SQL text, stack traces, or column names leak to response body. |
| T-36-SC | Tampering | pip installs | accept | No new packages. fastapi, pydantic, asyncpg already verified by prior phase audits. |
