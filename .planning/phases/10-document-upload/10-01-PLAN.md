    - Read `fileInput.files` into `selectedFiles` array
    - Clear `fileInput.value` after reading (so re-selecting the same file triggers change event)
    - If `selectedFiles.length > 0`:

      - Show `emptyState`
      - Hide `uploadForm`
      - Disable `uploadBtn`

    **3. `renderFileList()` function:**
    - Clear `fileListEl.innerHTML`
    - For each file in `selectedFiles`:
      - Format file size: if >= 1 MB show `(size / 1024 / 1024).toFixed(1) MB`, else show `(size / 1024).toFixed(0) KB`
      - Create a `.file-item` div:
        ```html
        <div class="file-item" data-index="${index}">
          <span class="file-name" title="${file.name}">${file.name}</span>
          <span class="file-size">${formattedSize}</span>
          <span class="file-status" id="file-status-${index}"></span>
        </div>
        ```
      - Append to `fileListEl`

    **4. Upload button click handler (`handleUpload`):**
    - Set `uploading = true`
    - Disable `uploadBtn` (set disabled attribute — per D-08)
    - Disable `chooseFilesBtn` (set disabled attribute — prevent changing selection mid-upload)
    - For each file in `selectedFiles` (sequential per D-09):
      a. Get status element: `document.getElementById('file-status-${index}')`
      b. Show spinner: set `statusEl.innerHTML = '<div class="spinner"></div>'`
      c. Create `FormData`: `const formData = new FormData(); formData.append('file', file);`
      d. Send fetch: `const response = await fetch('/documents/upload', { method: 'POST', body: formData })`
      e. If response ok (status 200-299):
         - Parse JSON: `const result = await response.json()`
         - Show first 8 chars of document ID: `const idShort = result.document_id.slice(0, 8)`
         - Replace spinner with checkmark ✓ in status element
         - Show success banner per UI-SPEC: "Uploaded: {filename} (ID: {idShort})" — green, auto-dismiss after 5s
      f. If response not ok:
         - Try to read error detail: `const errData = await response.json().catch(() => ({})); const reason = errData.detail || response.statusText`
         - Replace spinner with cross ✗ in status element
         - Show error banner per UI-SPEC: "Failed: {filename} — {reason}" — red, persists until dismissed
      g. On network error (fetch throws):
         - Replace spinner with cross ✗
         - Show error banner: "Failed: {filename} — Network error"
    - After all files processed:
      - Re-enable `chooseFilesBtn`
      - Set `uploading = false`
      - Reset state: `selectedFiles = []`, `fileInput.value = ''`, clear `fileListEl.innerHTML`
      - Hide `uploadForm`, show `emptyState`
      - Show a final success banner: "All files uploaded successfully" (green, auto-dismiss 5s)
      - **Per UI-SPEC:** "Upload area resets to initial" (Complete state)
    
    **5. `showBanner(message, type, autoDismiss)` function:**

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → FastAPI | User-uploaded file content sent via multipart POST. The API accepts the file, stores it in MinIO, and returns a document ID. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | File upload FormData | mitigate | The API endpoint limits uploads to 50 MB (MAX_UPLOAD_SIZE in api.py:470) and validates the filename. The browser's native `<input type="file">` restricts file selection to user-chosen files — no programmatic file injection from the UI. |
| T-10-02 | Information Disclosure | Error messages in banners | accept | Error banners display the server's `detail` field (e.g., "File exceeds maximum size of 50 MB"). This leaks no sensitive information as the API is unauthenticated and the details are already exposed through the API itself. |
| T-10-03 | Denial of Service | Multiple large file uploads | mitigate | Sequential upload (one file at a time) limits throughput. Each file is individually validated by the 50 MB server-side limit. No CSRF protection — the API is unauthenticated and accepts uploads by design. |
| T-10-SC | Tampering | No package installs | accept | No npm/pip/cargo packages are installed in this phase. All code is vanilla HTML/CSS/JS inline in index.html — no registry dependencies. No slopcheck gate needed. |
</threat_model>
