## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-05 | Tampering | Chunk text rendering in .doc-viewer-body | mitigate | **CRITICAL:** All chunk text rendered via `textContent` property of `Text` nodes and `<span>` elements built with `createTextNode` + `createElement`, assembled in a `DocumentFragment`. NEVER use `innerHTML`, `insertAdjacentHTML`, or string concatenation with angle brackets for chunk text. The renderHighlightedChunk() function uses exclusively: `document.createTextNode()`, `document.createElement('span')`, `span.textContent = ...`, and `fragment.appendChild()`. |
| T-37-06 | Tampering | Verbatim reference text in search/highlight | mitigate | Verbatim text used as literal search string via `indexOf()` (never `RegExp` — prevents regex metacharacter injection). The search string is never interpolated into HTML — only used for matching positions in the safe DOM construction loop. |
| T-37-07 | Tampering | Event detail fields in innerHTML (table rows) | mitigate | All user data in table cells (participant names, roles, location names, verbatim text, reference types) rendered via `escapeHtml()` before innerHTML. Description rendered via `textContent` on a `<div>`. |
| T-37-08 | Tampering | API error messages in DOM | mitigate | Error detail from API responses rendered via `escapeHtml()` in showBanner() and empty state cards. |
| T-37-09 | Information Disclosure | Document viewer exposes chunk text | accept | Chunk text is already accessible via the public API endpoint. The UI simply displays it — no new information exposure. Research tool, no sensitive data. |
| T-37-SC | Tampering | npm/pip/cargo installs | accept | No packages installed — pure vanilla JS inline code |

This is the single most important security rule in this plan.
