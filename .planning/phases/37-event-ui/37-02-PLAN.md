## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser JS → DOM (innerHTML) | User data rendered via escapeHtml() then innerHTML |
| Browser JS → API | Search/filter params sent to backend API |
| API response → DOM | JSON response fields rendered in table cells |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-02 | Tampering | Event table row rendering (innerHTML) | mitigate | All user data (event titles, location names, document filenames) passed through escapeHtml() before innerHTML injection. Event ID truncated to 8 chars via .slice() not vulnerable to injection. Participant/reference counts cast with String(). |
| T-37-03 | Tampering | Search/filter query params in URL | accept | Search term and document filter values are sent as URL query params to the backend API. Backend uses parameterized queries (Phase 36). Client-side, search text is only used for display (clear button, error messages via escapeHtml). |
| T-37-04 | Information Disclosure | API error detail in DOM/banner | mitigate | API error detail field rendered via escapeHtml() before insertion into showBanner() (which itself uses escapeHtml). Error messages in empty state cards use escapeHtml(). |
| T-37-SC | Tampering | npm/pip/cargo installs | accept | No packages installed — pure vanilla JS inline code |
</threat_model>
