## Interaction Contracts

### UI-01: Eventos Tab — Paginated List

**Entry point:** Nav tab "Eventos" added between "Referencias" and "Registros".

Nav button markup:
```
<button role="tab" aria-selected="false" aria-controls="tab-eventos" id="tab-btn-eventos" data-tab="eventos">Eventos</button>
```

**On first activation:** Fetch `GET /events?sort=time_start&order=desc&page=1&per_page=20`. Show deferred loading spinner (200ms delay).

**After first load:** Subsequent tab switches do not re-fetch unless the user explicitly refreshes (cache in JS variable `eventsData`, cleared on filter/sort change).

**Table columns (order):**

| Column | Header | Width | Data field | Format |
|--------|--------|-------|-----------|--------|
| ID | — | 100px | `event_id` | First 8 chars, mono font, color `#64748b` |
| Tiempo | Tiempo | 180px | `time_start` | Spanish locale date format: `toLocaleDateString('es-ES', {year:'numeric', month:'short', day:'numeric'})` |
| Título | Título | auto | `title` | Truncated with text-overflow ellipsis if needed |
| Lugar | Lugar | 160px | `location_name` | Fallback to "—" if null |
| Particip. | Particip. | 100px | `participant_count` | Right-aligned, tabular-nums |
| Refs | Refs | 100px | `reference_count` | Right-aligned, tabular-nums |

**Row behavior:** `cursor: pointer`. Click opens detail panel (UI-02). Hover: background `#f8fafc`.

**Sort:** Default `time_start` descending. No sort UI in this phase (per requirements, default sort only).

**Pagination:** Reuse `.documents-pagination` pattern: "← Anterior" / "Siguiente →" with "Página X de Y" in center. 20 items per page. Both buttons disabled at boundaries.

### UI-02: Event Detail Panel

**Opening:** Click event row → hide `#eventos-container`, show `#event-detail-panel`.

**Structure (top to bottom):**

1. **Header row:** "← Volver" button (`.btn-outline`) + event title as `h2` (24px, weight 600)
2. **Metadata card** (`.event-detail-meta`):
   - Tiempo: formatted time window (`{time_start}` – `{time_end}` with precision label)
   - Documento: `document_filename`
   - Confianza: `extraction_confidence` as percentage (e.g., "95%")
   - ID: full `event_id` in mono
3. **Description section:** Heading "Descripción" + `event.description` in `.event-detail-description` block
4. **Participants section:** Heading "Participantes" + table with columns: Nombre, Rol, Confianza
   - If no participants: "Sin participantes registrados" placeholder
5. **Locations section:** Heading "Lugares" + table with columns: Nombre, Tipo
   - If no locations: "Sin lugares registrados" placeholder
6. **References section:** Heading "Referencias" + table with columns: Texto Literal (truncated 120 chars), Tipo, Chunk
   - Each reference row: `.event-ref-clickable` (cursor pointer, hover highlight)
   - Clicking a reference row opens document viewer (UI-03) at the correct chunk

**Back button:** Click → hide detail panel, show `#eventos-container`, re-fetch event list.

**Data fetch:** `GET /events/{event_id}` on panel open. Show loading state in references section (`.documents-loading` with spinner) while fetching.

### UI-03: Document Viewer (Modal)

**Opening:** Click any reference row in the event detail panel → modal overlay opens. 

**Pre-fetch:** Before opening modal, fetch `GET /documents/{document_id}/chunks/{chunk_index}` to get the chunk text.

**Modal structure:**

1. **Backdrop:** Semi-transparent dark overlay (`.doc-viewer-backdrop`). Clicking backdrop closes modal.
2. **Modal container** (`.doc-viewer-modal`):
   - **Header** (`.doc-viewer-header`):
     - Left: Document filename (bold, 16px) + chunk indicator ("Parte N de M")
     - Right: Close button (✕, `.btn-icon`)
   - **Match navigation bar** (`.doc-viewer-match-nav`), visible when matches > 0:
     - "Referencia N de M" count display
     - "← Anterior" / "Siguiente →" match navigation buttons (`.btn-outline`, small)
   - **Body** (`.doc-viewer-body`):
     - Monospace, 14px, line-height 1.6, white-space pre-wrap, word-break break-word
     - Full chunk text rendered
     - Reference matches highlighted with `.doc-viewer-highlight` (yellow-200 background)
     - Currently active match: `.doc-viewer-highlight-active` (amber-500 background, white text)
     - Active match auto-scrolled into view (`element.scrollIntoView({ block: 'center' })`)
   - **Footer** (`.doc-viewer-footer`):
     - "← Parte anterior" / "Parte siguiente →" chunk navigation (`.btn-outline`)
     - Disabled at chunk boundaries (first/last part)

**Match highlighting logic:**
1. Load chunk text from endpoint
2. Find all occurrences of `reference.verbatim_text` in chunk text (case-insensitive, whole-word)
3. If multiple references exist: highlight all, set first as active
4. Render text by splitting on match positions, wrapping matched spans in `.doc-viewer-highlight` + `.doc-viewer-highlight-active` for active
5. Match nav buttons shift `.doc-viewer-highlight-active` class to next/previous match and scroll it into view

**Chunk navigation:**
- Click "← Parte anterior" → fetch `GET /documents/{document_id}/chunks/{chunk_index - 1}`, re-render body
- Click "Parte siguiente →" → fetch `GET /documents/{document_id}/chunks/{chunk_index + 1}`, re-render body
- On chunk change, re-apply highlighting for the same reference text in the new chunk (if it appears)
- Buttons disabled when chunk_index = 0 (prev) or last chunk (next)

**Close behavior:**
- Close button, backdrop click, or Escape key → remove modal from DOM
- Return to event detail panel (state preserved, no re-fetch needed)

### UI-04: Document Filter

**Location:** In toolbar row, a `<select class="status-filter">` element next to search input.

**Options:** 
- Default: `<option value="">Todos los documentos</option>`
- Populated dynamically from documents that have events: fetch document list, filter to those with events, render `<option>` per document (show filename, value = document_id)

**Behavior:** On change → reset to page 1, re-fetch events with `document={value}` query param. If empty value (todos): no document filter.

**Clear/reset:** The select has no explicit clear button. Selecting "Todos los documentos" is the clear action.

### UI-05: Title Search

**Location:** In toolbar row, a `<input type="text" class="search-input">` with placeholder "Buscar por título..."

**Debounce:** 300ms before fetch (reuse existing pattern).

**Clear button:** Appears when search has text. Click resets search, re-fetches with no search param.

**Behavior:** On input change (after debounce) → reset to page 1, re-fetch events with `search={value}` query param.

## Architecture Notes

### URL Design (API calls from UI)

| UI Action | API Endpoint | Method | Notes |
|-----------|-------------|--------|-------|
| Load event list | `/events?page={n}&per_page=20&sort=time_start&order=desc[&search={q}][&document={id}]` | GET | Existing v7 route |
| Load event detail | `/events/{event_id}` | GET | Returns full detail with locations, participants, references |
| Load chunk text | `/documents/{document_id}/chunks/{chunk_index}` | GET | Returns `text`, `offset_start`, `offset_end` |

### JS Architecture

All new JavaScript code lives in the existing `<script>` block in `index.html`. No new files, no module system.

**State variables to add:**
```
let eventosCurrentPage = 1;
let eventosSearchTerm = '';
let eventosDocumentFilter = '';
let eventosLoadingFlag = false;
let eventosData = null;  // cache for tab switches
let currentEventId = null;  // for back navigation
let currentEventDetail = null;  // cached detail data
let eventosSearchDebounceTimer = null;
```

**Key functions to add:**
- `fetchEventos()` — fetch from `/events` with pagination/filter/search params
- `renderEventos(data)` — render table rows and pagination
- `showEventDetail(eventId)` — fetch and show detail panel
- `renderEventDetail(data)` — populate detail panel sections
- `hideEventDetail()` — back to event list
- `openDocViewer(eventId, refIndex)` — open document viewer modal for a reference
- `renderDocViewer(chunkData, verbatimText, refIndex, totalRefs)` — render chunk text with highlighting
- `navigateChunk(direction)` — next/prev chunk navigation
- `navigateMatch(direction)` — next/prev match navigation
- `populateDocumentFilter()` — fetch and populate document filter dropdown

### Tab Registration

Add "Eventos" to the `sections` object and `tabs` iteration. Add `eventos` to `onTabClick` switch logic:
```
if (tabName === 'eventos') fetchEventos();
```

## States

Every UI section must handle these states:

### Event List

| State | Visual |
|-------|--------|
| **Loading** | `.eventos-loading` visible (spinner + "Cargando eventos..."), table hidden |
| **Empty (no data)** | `.eventos-empty` visible: heading "No se encontraron eventos", body "Los eventos aparecerán aquí después de procesar los documentos" |
| **Empty (filtered)** | Same card, body "Ningún evento coincide con los criterios de búsqueda" |
| **Data** | Table visible, pagination visible |
| **Error** | `.eventos-empty` visible with error message "Error al cargar eventos: {message}". Also show `.banner-error`. |

### Event Detail

| State | Visual |
|-------|--------|
| **Loading references** | `.documents-loading` in references section (spinner + "Cargando referencias...") |
| **Data** | All sections rendered |
| **Empty participants** | "Sin participantes registrados" placeholder |
| **Empty locations** | "Sin lugares registrados" placeholder |
| **Empty references** | "Sin referencias vinculadas" placeholder |
| **Error** | References section shows error message. Banner displayed. |

### Document Viewer

| State | Visual |
|-------|--------|
| **Loading chunk** | Loading state in modal body (spinner centered) |
| **Chunk loaded** | Text rendered with highlights |
| **No matches in chunk** | Text rendered without highlights; match nav hidden |
| **Single match** | Match nav shows "Referencia 1 de 1", prev/next match buttons disabled |
| **Multi-match** | Match nav active, highlighting on all with one active |
| **First chunk** | "← Parte anterior" disabled in footer |
| **Last chunk** | "Parte siguiente →" disabled in footer |
| **Error loading chunk** | Error message in modal body, close button still available |
