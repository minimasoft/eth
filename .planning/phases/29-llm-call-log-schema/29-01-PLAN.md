    -- v6.1 Schema Evolution -- Phase 29: LLM Call Log

    -- pairs, token usage, cost, duration, and metadata per document.
    -- All fields are nullable DEFAULT null for additive safety.

    2. **CREATE TABLE IF NOT EXISTS llm_call_log** with these fields (all nullable DEFAULT null):
       - `id TEXT PRIMARY KEY` — matches existing TEXT PK pattern (llm_usage, document_event_log). Phase 30 will define the ID generation strategy (likely deterministic SHA256 for replay safety).
       - `prompt_text TEXT DEFAULT NULL` — TEXT type for arbitrarily large LLM outputs (per RESEARCH Pitfall 2: avoid VARCHAR)
       - `response_text TEXT DEFAULT NULL` — same TEXT rationale
       - `prompt_tokens INTEGER DEFAULT NULL`
       - `completion_tokens INTEGER DEFAULT NULL`
       - `total_tokens INTEGER DEFAULT NULL`
       - `cached_tokens INTEGER DEFAULT NULL`
       - `cost REAL DEFAULT NULL`
       - `duration_ms INTEGER DEFAULT NULL`
       - `model TEXT DEFAULT NULL`
       - `activity_type TEXT DEFAULT NULL` — free-form label (e.g., 'extract_events', 'resolve_entities'), no CHECK constraint
       - `document TEXT NOT NULL REFERENCES document(id) ON DELETE CASCADE` — matches llm_usage FK pattern (schema.sql:119). NOT NULL on FK (log cannot exist without a parent document). ON DELETE CASCADE required per PIPE-03 cascade behavior.
       - `timestamp TIMESTAMPTZ DEFAULT NULL` — nullable timestamp for chronological ordering

       CRITICAL: Every field EXCEPT `id` (PK) and `document` (FK) must use `DEFAULT NULL` and omit `NOT NULL`. Do NOT copy `NOT NULL` or `CHECK` constraints from the `llm_usage` analog table. This is the primary difference from `llm_usage` and what RESEARCH.md identifies as Pitfall 2.

    3. **CREATE INDEX IF NOT EXISTS idx_llm_call_log_document ON llm_call_log(document);** — matches existing naming convention `idx_<table>_<column>` as seen in schema.sql lines 135-148.

    4. **CREATE INDEX IF NOT EXISTS idx_llm_call_log_timestamp ON llm_call_log(timestamp);** — separate index, matching SCH-02 requirement for "Index exists on timestamp field" (per RESEARCH Pitfall 3: do NOT use a composite index instead of separate indexes).

    Follow the formatting style of the existing schema.sql:
    - One field per line with leading 4-space indent
    - Commas after each field definition
    - Closing `);` on its own line
    - No blank line between the CREATE TABLE statement and the CREATE INDEX statements
    - Use `CREATE TABLE IF NOT EXISTS` for idempotency (every table in schema.sql uses this pattern)
    - Use `CREATE INDEX IF NOT EXISTS` for idempotency (every index in schema.sql uses this pattern)
    - Do NOT add trailing semicolons after the last statement — the file already has a semicolon on the last index line.
  </action>
