# Phase 11 — Plan 01: Document List

**Objective:** Implement the paginated document list UI in the Documents tab with backend `GET /documents` endpoint, including search, status filtering, and pagination controls.

**Context:** Phase 11 (Document List)

---

## Tasks

### Task 1 — Backend: `GET /documents` endpoint

**Type:** auto

**Files:**
- `src/eth_pipeline/api.py`

**Implementation:**
1. Add `Query` to FastAPI imports.
2. Add `DocumentListItem` and `DocumentListResponse` Pydantic models after `DocumentStatus`.
3. Add `list_documents` endpoint after `get_document` using the same SurrealDB connection pattern.
4. Build dynamic WHERE clause — `LIKE` on filename for search, exact match on status.
5. Query count with `SELECT count() AS total` and data with `LIMIT $per_page START $offset`.
6. Parse RecordID from SurrealDB response for the `document_id` field.
7. Convert datetime objects to ISO strings consistent with `get_document`.
8. Return 503 when DB unavailable, 502 on query failure.

**Verification:**
- Python syntax check passes.
- All existing route decorators are preserved.
- New models appear in class definitions.

### Task 2 — Frontend: Document list UI

**Type:** auto

**Files:**
- `src/eth_pipeline/static/index.html`

**Implementation:**

## Decisions
- Status badge colors match UI-SPEC: pending (gray), processing (blue), processed (green), failed (red).
- Search debounce at 300ms (standard UX pattern).
- Table defaults to newest-first sort by `created_at DESC`.
- Fixed 20 items per page (no per-page selector).
