  <name>Task 2: Create storage.py client factory + add minio dependency</name>
  <files>
    src/eth_pipeline/storage.py
    pyproject.toml

  <action>
    Create `src/eth_pipeline/storage.py` mirroring the `db.py` pattern:

    - Module-level constants: `DEFAULT_ENDPOINT`, `DEFAULT_ACCESS_KEY`, `DEFAULT_SECRET_KEY`, `DEFAULT_BUCKET`, `DEFAULT_SECURE`, `MAX_RETRIES`, `RETRY_DELAY_S`
    - Default values from env vars (MINIO_ENDPOINT, MINIO_ACCESS_KEY, MINIO_SECRET_KEY, MINIO_BUCKET, MINIO_SECURE), with fallback to `minio:9000`, `minioadmin`, `minioadmin`, `eth-documents`, `False`.
    - A `_connect()` helper (sync, not async — the `minio` SDK is synchronous) that creates a `minio.Minio` client, calls `client.bucket_exists()` on `DEFAULT_BUCKET` as a connectivity check, and returns the client. Retry loop with same MAX_RETRIES/RETRY_DELAY_S pattern as db.py.
    - A `get_storage()` context manager that calls `_connect()`, yields the client, and tears down on exit (no-op for sync client).
    - Since `minio.Minio` is synchronous but the rest of the stack is async, provide both a sync context manager (`@contextlib.contextmanager`) and an async one (`@contextlib.asynccontextmanager`) that wraps the sync connect in `asyncio.to_thread()`. Name the async version `get_storage_async`.

    Auto-detection of `MINIO_SECURE`: parse env var — `"true"` / `"1"` / `"yes"` → `True`, anything else → `False`.

    Add `"minio>=7.2.0"` to the `dependencies` list in `pyproject.toml`, keeping alphabetical order with the existing entries.

    Both `max_retries` / `retry_delay` parameters should be configurable on `get_storage()` and `get_storage_async()` for testability.
  </action>

  <action>
    Create `scripts/init_bucket.py` mirroring the `init_schema.py` pattern:

    - Stdlib-only (urllib, os, sys, argparse) — the MinIO REST API is S3-compatible and can be called via signed HTTP requests, BUT a simpler approach: use the `minio` package directly (already added to pyproject.toml). Since the script runs via `uv run python scripts/init_bucket.py` inside the container where `minio` is installed, that's fine.
    - Use `minio.Minio` client directly (as imported from the package, not from `eth_pipeline.storage`).
    - Read env vars: `MINIO_ENDPOINT` (default `minio:9000`), `MINIO_ACCESS_KEY` (default `minioadmin`), `MINIO_SECRET_KEY` (default `minioadmin`), `MINIO_BUCKET` (default `eth-documents`), `MINIO_SECURE` (default `false`).
    - Add `--check` flag for connectivity-only mode (like `init_schema.py`).
    - On run: connect to MinIO, check if bucket exists via `client.bucket_exists()`, create it if not via `client.make_bucket()`, print result, exit 0.
    - Handle `S3Error` (bucket already exists) gracefully — it's idempotent.
    - Graceful degradation if MinIO is not reachable: print warning and exit 1.

    Update `src/eth_pipeline/schema.surql` — add two new fields to the `document` table (after `mime_type`):

    ```
    DEFINE FIELD blob_format ON TABLE document TYPE string | null
        DEFAULT null
        COMMENT 'Storage format of the original binary blob: "minio" (object-stored), null (inline base64 for legacy)';

    DEFINE FIELD blob_path ON TABLE document TYPE string | null
        DEFAULT null
        COMMENT 'S3 object path within the eth-documents bucket when blob_format="minio" (e.g. doc/{id}.pdf); null for legacy inline-stored documents';
    ```

    These are nullable so existing base64-stored documents remain fully valid.
