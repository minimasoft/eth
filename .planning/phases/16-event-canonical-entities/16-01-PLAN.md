  <name>Task 1: Create create_event_canonical_entities_activity in activities.py</name>
  <files>src/eth_pipeline/activities.py</files>
  <action>
    Add a new activity `create_event_canonical_entities_activity` to `activities.py` following the same pattern as `resolve_entities_activity` (same signature: `document_id, result` → `dict`).

    **Signature:** `async def create_event_canonical_entities_activity(document_id: str, result: dict) -> dict:`

    **Behavior (per locked decisions):**
    
    1. **DB connection (per D-01):** Single batch activity per document. Use `_db_params()`, `ProcessingLogger`, `async with get_db(**params) as db:` — same pattern as all other activities. Initialize `_log = ProcessingLogger(params)` at the top.

    2. **Nullify step (per D-03):** Delete existing event-type canonical entities scoped to this document:
       ```sql
       DELETE canonical_entity WHERE entity_type = 'event' AND properties.document_id = $doc_id
       ```
       Also delete corresponding `event_entity_link` records that reference those now-deleted event entities:
       ```sql
       DELETE event_entity_link WHERE event IN (
         SELECT id FROM canonical_entity WHERE entity_type = 'event' AND properties.document_id = $doc_id
       )
       ```
       (Run nullify before querying events — the prior run's entities are gone, fresh ones will be created.)

    3. **Query events:** Same pattern as resolve_entities_activity — query events for this document:
       ```sql
       SELECT * FROM event WHERE document = $doc_ref
       ```

    4. **Per-event entity creation (per D-02, D-04):** For each event, create a `canonical_entity` record:
       - `entity_type: "event"`
       - `name:` `f"Event: {que_paso[:80].strip()}..."` — first 80 chars, strip trailing whitespace, append `"..."` if truncated beyond 80 chars. If que_paso is shorter than 80 chars, use it as-is without ellipsis.
       - `properties:` dict with these keys mapped from event fields (per D-02):
         - `title: que_paso[:80]` — same truncation as name body, no ellipsis
         - `description: que_paso` — full que_paso text
         - `time_range: tiempo` — event.tiempo value (string or null)
         - `location: espacio` — event.espacio value (string or null)
         - `participants: humanos` — event.humanos value (string or null)
         - `objects: objetos` — event.objetos value (string or null)
         - `document_id: document_id` — the input parameter, for scoping (used in nullify step)
       - Use `db.create("canonical_entity", data)` or raw `CREATE canonical_entity CONTENT { ... }` — whichever pattern fits best (follow store_extraction_results_activity's `CREATE ... CONTENT` pattern for field control).

    5. **RELATE edges (per D-05):** After creating each event entity, for each of the event's text fields (espacio, humanos, objetos), query existing canonical entities by name matching:
       - For `espacio` text value: query `SELECT id FROM canonical_entity WHERE entity_type = 'place' AND name CONTAINS $value`
       - For `humanos` text value: query `SELECT id FROM canonical_entity WHERE entity_type = 'person' AND name CONTAINS $value`
       - For `objetos` text value: query `SELECT id FROM canonical_entity WHERE entity_type = 'object' AND name CONTAINS $value`
       - **Link threshold (per D-05 comment):** If entity name contains the verbatim text OR the verbatim text contains the entity name, create a link.
       - For each matched entity, create an `event_entity_link` record (per schema at schema.surql lines 278-305):
         ```
         CREATE event_entity_link CONTENT {
           event: $event_entity_rid,
           entity: $matched_entity_rid,
           relationship_type: 'involves',
           role: $role,  -- 'location' for espacio matches, 'subject'/'participant' for humanos, 'object' for objetos
           confidence: 0.7  -- heuristic, not LLM-derived
         }
         ```

    6. **Skip if no events:** Early return `{"document_id": ..., "events_processed": 0, "entities_created": 0, "links_created": 0}` if no events found.

    7. **Error handling:** Same structured error handling as `resolve_entities_activity` — try/except for `ConnectionError` and `Exception`, log via `_log.log()` and `activity.logger`, return error dicts.

    8. **Return value:** `{"document_id": document_id, "events_processed": N, "entities_created": N, "links_created": N}`

    **Edge cases:**
    - Event fields (espacio, humanos, objetos) may be None or empty string — skip RELATE matching if so (avoid matching every entity with an empty string)
    - No existing entities match a text value — continue without creating a link (not an error)
    - Entity already linked from previous run — nullify step handles this by deleting before recreation
    - `que_paso` less than 80 chars — use as-is, no ellipsis; non-empty always has at least "Event: " prefix

    **Pattern references:**
    - Follow `resolve_entities_activity` for: `_db_params()`, `ProcessingLogger`, `async with get_db()`, `_extract_query_results()`, return dict shape, error handling structure.
    - Follow `store_extraction_results_activity` for: `CREATE ... CONTENT` SQL pattern, event field access (`.get("que_paso", "")`).
