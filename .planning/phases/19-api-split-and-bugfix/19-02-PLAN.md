# Plan 02: Split api.py into Route Modules

## Goal

Reduce `api.py` from 2,596 lines to a <50-line entry point by splitting into focused modules.

## Proposed Module Layout

```
src/eth_pipeline/api/
  __init__.py        # Re-exports FastAPI app (what other files import)
  models.py          # All 22 Pydantic request/response models
  lifespan.py        # lifespan() async context manager
  routes/
    __init__.py
    documents.py     # create, upload, status, list, clear events, delete
    entities.py      # list, merge, split
    references.py    # list
  graphql.py         # GraphQL proxy endpoint + _surreal_http_url helper
```

## Migration Strategy

### Step 1: Create package structure

Create `api/` directory with `__init__.py` and all submodules.

### Step 2: Extract models

Move all 22 `class *Model(BaseModel)` definitions to `api/models.py`. Keep imports clean — models are referenced by route modules and lifespan.

### Step 3: Extract lifespan

Move `lifespan()` to `api/lifespan.py`. Import necessary types from FastAPI.

### Step 4: Extract route groups

One module per route group:

| Module | Endpoints | Lines |
|--------|-----------|-------|
| `routes/documents.py` | root, health, create, upload, status, list, clear events, delete | ~900 |
| `routes/entities.py` | list entities, merge, split | ~600 |
| `routes/references.py` | list references | ~200 |

Each module creates an `APIRouter(tags=[...])`, defines endpoint functions, and is included in the main app via `app.include_router()`.

### Step 5: Extract GraphQL proxy

Move `_surreal_http_url()` and `graphql_proxy()` to `api/graphql.py`.

### Step 6: Rewrite `api.py` as thin entry point

```python
from eth_pipeline.api import app  # or similar
```

The old `api.py` becomes a re-export shim so existing imports from other files still work.

### Step 7: Verify

- `python -c "import ast; ast.parse(open('src/eth_pipeline/api.py').read())"`
- `python -c "from eth_pipeline.api import app; print(type(app))"`
- Each route module is importable independently
- `scripts/run_worker.py`, `worker.py`, and any other file importing from `eth_pipeline.api` still works
- Start dev server, hit a few endpoints to confirm 200s

## Backward Compatibility

- `eth_pipeline.api` package preserves `app` export at package level
- Other modules that `from eth_pipeline.api import ...` continue to work
- FastAPI app object identity preserved (same app, just built in `__init__.py`)
