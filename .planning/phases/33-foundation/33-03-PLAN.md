    **Part B — scripts/init_schema.py:**

    Modify `init_schema.py` to stamp Alembic after `apply_schema()` completes. Add the following after the `apply_schema()` call in `main()`:

    ```python
    # After schema is applied, stamp Alembic at the current head so future
    # migrations know the schema is up to date.
    try:
        import subprocess
        result = subprocess.run(
            ["uv", "run", "alembic", "stamp", "head"],
            capture_output=True, text=True, timeout=30,
        )
        if result.returncode != 0:
            print(f"⚠  Alembic stamp failed: {result.stderr.strip()}")
            print("   Schema applied — manual `alembic stamp head` may be needed.")
        else:
            version = result.stdout.strip()
            print(f"✔ Alembic stamped at head: {version}")
    except FileNotFoundError:
        print("⚠  alembic CLI not found — skipping Alembic stamp (schema applied).")
    except subprocess.TimeoutExpired:
        print("⚠  Alembic stamp timed out — skipping (schema applied).")
    ```

    Also add `import subprocess` at the top of the file alongside the existing imports (stdlib import, grouped with `asyncio`, `os`, `sys`, `pathlib`).

    The stamp is non-fatal — if Alembic is not available (e.g., in a minimal deployment), the schema still gets applied. This is a "best effort" integration per RESEARCH.md Pitfall 4 mitigation.
  </action>
