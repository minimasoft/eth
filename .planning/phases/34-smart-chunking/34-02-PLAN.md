<objective>
Implement SmartChunker — a sentence-aware, balanced document chunker using NLTK Punkt for Spanish sentence boundary detection — and wire it into the chunk_document_activity with schema_version routing.

Purpose: Replace the naive RecursiveCharacterTextSplitter (which splits mid-sentence on Spanish abbreviations like "S.L.", "art.") with NLTK Punkt's sentence-aware tokenizer (CHK-02). Balance chunks around CHUNK_SIZE_TARGET to eliminate extreme skew (CHK-01). Track part-provenance via offset_start/offset_end and part_index=chunk_index (CHK-04). Make chunk size configurable via CHUNK_SIZE_TARGET env var (CHK-03).

Output: A modified chunker.py with SmartChunker alongside the preserved DocumentChunker, and a modified chunk_document.py that routes v6→old, v7→new.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| document.text_content → SmartChunker | User-uploaded document text is processed in-memory by NLTK Punkt. Extremely large texts (>10MB) could cause memory exhaustion. |
| SmartChunker → document_chunk table | Chunk text is stored in PostgreSQL via parameterized queries. No user input is interpolated into SQL. |
| NLTK Spanish Punkt model | Loaded from local filesystem (downloaded at Docker build time). No network call at runtime. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-03 | Denial of Service | SmartChunker.chunk() | mitigate | Short-text early exit (≤ target_size) returns single chunk without NLTK processing. Large texts get processed by NLTK which streams incrementally. For very large texts (>10MB), the `target_size` limit naturally bounds per-chunk processing. Phase 34 does not add a hard max-size guard — this is acceptable for a single-user research tool processing legal judgments (typically < 5MB). |
| T-34-04 | Tampering | SQL INSERT in chunk_document.py | mitigate | All chunk storage uses asyncpg parameterized queries ($1, $2, ...). The existing code already follows this pattern (confirmed in chunk_document.py lines 62-74). No string interpolation in SQL. |
| T-34-05 | Information Disclosure | chunk text stored in PostgreSQL | accept | Chunk text is stored as plaintext in the `document_chunk.text` column. This is identical to the existing v6 behavior. No PII, credentials, or sensitive data in legal judgment text. Acceptable risk for a single-user research tool. |
| T-34-06 | Elevation of Privilege | NLTK model loaded from container filesystem | mitigate | The Punk model is downloaded at Docker build time from nltk.org (trusted source) and stored in the container filesystem. At runtime, `_get_punkt_tokenizer('spanish')` loads from local disk — no network call. |
</threat_model>
