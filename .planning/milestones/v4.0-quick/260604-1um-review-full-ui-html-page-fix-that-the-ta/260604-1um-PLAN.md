<objective>
Fix two layout regressions in the single-page ETH web UI (`src/eth_pipeline/static/index.html`):

1. **Tab-bar vertical scrollbar** — The `<nav>` tab bar has `overflow-x: auto` for horizontal tab scrolling, but browsers that implicitly enable vertical overflow alongside horizontal overflow render a useless tiny vertical scrollbar on the 44px-tall bar.
2. **Narrow document view forcing horizontal scroll** — The `<main>` container is clamped to `max-width: 960px`, which is too narrow for the 9-column documents table. Users must horizontally scroll within the cramped `.table-container` instead of the table simply spanning available screen width.

Purpose: Eliminate distracting scrollbar artifacts and let data tables breathe at wider viewport widths.
Output: Single modified file — `src/eth_pipeline/static/index.html` — with two targeted CSS changes.
</objective>

<task type="auto">
  <name>Fix 1: Prevent vertical scrollbar on tab-bar nav</name>
  <files>src/eth_pipeline/static/index.html</files>
  <action>
    In the `nav` CSS rule (currently around line 37, selector: `nav { position: sticky; … overflow-x: auto; … }`),
    add `overflow-y: hidden;` after the existing `overflow-x: auto;` declaration.

    The root cause is some browsers auto-enable vertical overflow scrollbars when horizontal overflow is
    set to `auto` and the content box height is tight (44px nav with 44px-tall buttons + 2px border-bottom
    can trigger sub-pixel vertical overflow). `overflow-y: hidden` is the standard fix — it tells the
    browser to clip vertical overflow without showing a scrollbar, while preserving the horizontal scrolling
    behavior controlled by `overflow-x: auto`.

    Do NOT change any other property on the `nav` rule. The horizontal tab scrolling must continue to work.
  </action>
  <verify>
    <automated>rg "overflow-y:\s*hidden" src/eth_pipeline/static/index.html -c</automated>
  </verify>
  <done>
    The `nav` CSS block contains `overflow-y: hidden;` alongside the existing `overflow-x: auto;`.
    The tab bar renders identically on all tabs, but no vertical scrollbar appears regardless of
    browser engine (Chromium, Firefox, WebKit).
  </done>
</task>

<task type="auto">
  <name>Fix 2: Widen main container so document tables do not force horizontal scrolling</name>
  <files>src/eth_pipeline/static/index.html</files>
  <action>
    In the `main` CSS rule (currently around line 78: `main { max-width: 960px; margin: 0 auto; padding: 24px; }`),
    change `max-width` from `960px` to `1400px`.

    The documents table has 9 columns (ID, Archivo, Fecha de Subida, Estado, Refs, Ents, Fragmentos,
    Palabras, Acciones). At 960px the table is forced to horizontally scroll within a narrow `.table-container`
    wrapper. At 1400px the table has enough room to display all columns without horizontal overflow on
    standard desktop viewports (1440px+), while still remaining comfortably readable on ultrawide screens
    thanks to the `max-width` clamp and `margin: 0 auto` centering.

    Do NOT remove the `max-width` entirely — keep it centered. Do NOT change any other property on the `main` rule.
  </action>
  <verify>
    <automated>rg "max-width:\s*1400px" src/eth_pipeline/static/index.html -c</automated>
  </verify>
  <done>
    The `main` element has `max-width: 1400px`. On viewports ≥ 1400px the documents table renders all
    9 columns without horizontal scrolling. The `.table-container`'s `overflow-x: auto` still functions
    as a safety net for very narrow viewports (mobile / tablet), but on standard desktop widths the table
    fits naturally.
  </done>
</task>
