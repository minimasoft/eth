# Quick Task 260604-3p8: Fix cascade delete and simplify tests

## What was done

### Fix 1: SurrealDB v3 DELETE parameter binding (root cause of 463 orphan references)

The `delete_document()` and `clear_document_events()` endpoints passed `doc_ref` as a string `"document:{id}"` to DELETE query parameters. SurrealDB v3 cannot properly bind string document references against `record<document>` fields in DELETE queries — this was confirmed by the existing comment in `activities.py:1510-1511`. The fix uses `RecordID("document", id)` objects consistently, which was already how the SELECT queries and the final `DELETE document` statement worked.

### Fix 2: Added `event_entity_link` cleanup

Both `DELETE /documents/{id}` and `DELETE /documents/{id}/events` now delete `event_entity_link` records before deleting events. This matches the pattern used in `create_event_canonical_entities_activity()` (activities.py:1080-1087).

### Fix 3: Added `document_event_log` cleanup

`DELETE /documents/{id}` now deletes processing log entries via `DELETE document_event_log WHERE document = $doc_id`.

### Test simplification

- `pipeline.test.ts` (Test 7): Removed 1s delay, pre-delete document check, JSON parse validation of response body, and console.log noise.
- `pipeline_v2.test.ts` (Test 4): Removed sqlCountChunks retry loop (3 attempts with 500ms delays) and pre-delete chunk count check.
- `pipeline_v4.test.ts`: Added comprehensive cascade-delete E2E test (Test Group 5) that verifies zero references, events, chunks, logs, and zero orphan references after full document deletion.
