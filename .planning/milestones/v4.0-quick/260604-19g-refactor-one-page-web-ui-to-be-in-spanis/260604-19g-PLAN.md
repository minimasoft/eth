<task type="auto">
  <name>Task 2: Eliminate content-refresh flicker with deferred loading</name>
  <files>src/eth_pipeline/static/index.html</files>
  <action>
Replace the immediate-loading-spinner pattern in all four data tabs (documents, entities, references, logs) with a deferred-loading pattern that preserves existing content during fast fetches. The flicker happens because `showXLoading()` hides the table and shows a spinner immediately, even for sub-100ms fetches.

**Pattern to implement for each tab:**

1. Remove the call to `showXLoading()` at the top of each `fetchX()` function. Instead, set a 200ms timeout that shows loading ONLY if the fetch hasn't completed.

2. In each `renderX()` function, clear the deferred-loading timeout and call `hideXLoading()` (which is now a no-op most of the time).

3. Add one shared deferred-loading utility at the top of the `<script>`:

```js
// Deferred loading: only show loading spinner if fetch takes >200ms
const deferredLoaders = {};
function deferredLoading(key, showFn, hideFn) {
  deferredLoaders[key] = setTimeout(function() {
    showFn();
  }, 200);
  return {
    done: function() {
      clearTimeout(deferredLoaders[key]);
      hideFn();
    }
  };
}
```

4. Rewrite each `fetchX()` function:

For `fetchDocuments()` (line 1135): Replace `showDocLoading()` with a deferred loader. Keep the loading flag guard. Example refactor:
```js
async function fetchDocuments() {
  if (docsLoadingFlag) return;
  docsLoadingFlag = true;
  var loader = deferredLoading('docs', showDocLoading, hideDocLoading);
  // ... fetch logic ...
  try {
    // ... existing fetch ...
    renderDocuments(data);
  } catch (err) {
    loader.done();
    // ... existing error handling ...
  } finally {
    docsLoadingFlag = false;
  }
}
```

5. In `renderDocuments()` (line 1171): Add `var loader = deferredLoaders['docs']; if (loader) { clearTimeout(loader); hideDocLoading(); }` at the top.

Apply the same pattern to: `fetchEntities()` (line 1353) + `renderEntities()` (line 1389), `fetchReferences()` (line 1509) + `renderReferences()` (line 1545), and `fetchLogs()` (line 1707) + `renderLogs()` (line 1739).

**Key behavior after the change:**
- First ever load: spinner appears after 200ms if data hasn't arrived yet
- Subsequent search/filter/pagination: existing content stays visible; only updates in-place when new data arrives
- Slow connections (200ms+): spinner appears as before
- Fast responses: no visual flash — old data seamlessly replaced by new data
