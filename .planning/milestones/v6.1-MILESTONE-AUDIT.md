## Tech Debt Identified

### TD-01: Summary is page-level, not document-level (MODERATE)

**Files:** `src/eth_pipeline/static/index.html` lines 2750-2751 (stub), 2680-2741 (page-level computation)
**Phase:** 32
**Requirement:** UI-03

**Issue:** The spec and plan called for `GET /documents/{id}/llm-calls/summary` as a dedicated endpoint. The fix commit `89e3494` intentionally made `fetchLlmCallsSummary` a stub and moved summary computation to `renderLlmCalls()`, which iterates only the current page's items. For documents with multi-page LLM calls (e.g., 100 calls across 5 pages), the summary shows per-page aggregates, not document-wide totals.

**Decision:** The implementation chose client-side page-level aggregation over a summary endpoint. This is functional but misleading for documents with >20 LLM calls. Two paths to resolve:
1. **Backend:** Create `GET /documents/{id}/llm-calls/summary` endpoint with `SELECT COUNT(*), SUM(prompt_tokens), ... FROM llm_call_log WHERE document=$1`
2. **Frontend:** Fetch all pages and compute client-side (works but defeats pagination)

### TD-02: Missing ARIA attributes on sub-tab buttons (LOW)

**Files:** `src/eth_pipeline/static/index.html` lines 1251-1252
**Phase:** 32

**Issue:** Sub-tab buttons lack `role="tab"`, `aria-selected`, and `aria-controls` attributes present on main navigation tabs (lines 993-998). Screen readers cannot identify them as tab controls. No keyboard arrow key support.

**Fix:** Add `role="tab"`, `aria-selected`, `aria-controls` to sub-tab buttons and update `switchLogsSubtab()` to toggle `aria-selected`. Add Left/Right Arrow key handler.

### TD-03: No keyboard navigation on expandable rows (LOW)

**Files:** `src/eth_pipeline/static/index.html` lines 2783-2787
**Phase:** 32

**Issue:** Expandable LLM call rows are click-only with no Enter/Space toggle. Rows lack `tabindex="0"`.

**Fix:** Add `keydown` handler for Enter/Space key to `toggleLlmCallRow()`.

### TD-04: Root API endpoint missing llm-calls entry (LOW)

**Files:** `src/eth_pipeline/api/routes/documents.py` line 56
**Phase:** 31

**Issue:** Root API info endpoint does not list `/documents/{document_id}/llm-calls` in its `endpoints` dict, reducing API discoverability.

**Fix:** Add entry matching existing pattern.

- **All 10 requirements are functionally delivered.** The llm_call_log table exists, all 3 pipeline activities record calls, the API endpoint returns paginated results with full text, and the UI shows the sub-tab with expandable rows.
- **Phase 31 and 32 have thorough verification and review artifacts.** The API endpoint is clean (0 critical, 0 warning). Phase 32's critical CSS bug was found in review and fixed.
- **The architecture is consistent.** The SHA256 deterministic ID + UPSERT pattern from v5.0's `llm_usage` is faithfully reused. Cascade delete paths are covered. The API follows existing envelope patterns.

### What needs attention

1. **Phase 30 has no verification evidence.** We cannot prove the pipeline actually records LLM calls into the table without running it. This is the highest-priority gap.
2. **Phase 29's validation was never formalized.** The strategy document remains in draft.
3. **The summary is page-level, not document-level.** For documents with >20 LLM calls, users will see incorrect aggregated totals.
4. **All documentation is stale.** ROADMAP, REQUIREMENTS.md traceability table, and the root API info endpoint all need updates.

### Recommendation

1. **Before shipping v6.1:** Add 30-VERIFICATION.md with E2E verification steps for PIPE-01/02/03. The fix commit `89e3494` already addressed the critical CSS bug; the remaining items (TD-01 through TD-04) are non-blocking tech debt.
2. **After shipping v6.1:** File tickets for TD-01 (document-level summary) as the most impactful improvement — it's misleading for any document with multi-page LLM results.
