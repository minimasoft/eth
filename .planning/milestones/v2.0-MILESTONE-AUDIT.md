## Code Quality

### Strengths
- **Consistent patterns**: `storage.py` mirrors `db.py` (env-var-driven, context manager, retry loop); activities follow per-connection pattern (D012)
- **Protocol-based design**: `ContentExtractor` protocol enables future format support without modifying existing code
- **Chunk transparency enforced**: `extract_events_activity` always receives full reconstructed text — no chunk leakage
- **Robust error handling**: Typed exceptions (`ExtractorQualityError` with reasons), degraded mode fallback (MinIO unavailable → base64), quality gates for empty/scanned PDFs
- **Thorough documentation**: All modules have module-level docstrings, all classes/methods have Google-style docstrings
- **Safety patterns**: Delete-then-recreate idempotency, nullify-then-recreate for Temporal replay, skipIfDegraded for CI resilience
- **Edge cases covered**: Short text (single chunk), empty text (single empty chunk), empty page_offsets normalization
- **3 bugs found and fixed** during Phase 8 testing (missing GET route, nullable text_content, NULL coercion)

### Observations
- All new code has type annotations; no `Any` or `# type: ignore` in new files
- All imports are lazy where optional (extractors.py, chunker.py) — modules load without dependencies
- Worker registration is comprehensive — both `worker.py` and `scripts/run_worker.py` register all activities
- API backward compatibility maintained — `POST /documents` unchanged, `POST /documents/upload` added alongside
