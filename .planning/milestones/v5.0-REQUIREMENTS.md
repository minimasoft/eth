# Requirements: Espacio Tiempo Humanos

**Defined:** 2026-06-04
**Milestone:** v5.0 LLM Cost & Usage Tracking
**Core Value:** Every extracted event must be traceable to its exact source text in the original document, and every resolved entity must show its evidential references.

## v5.0 Requirements

Requirements for this milestone. Each maps to roadmap phases.

### Token Capture & Storage

- [ ] **TOKN-01**: New `llm_usage` SurrealDB table for per-LLM-call token/cost data — schemaful, append-only, no entry cap
- [ ] **TOKN-02**: OpenRouterProvider extracts usage data (prompt_tokens, completion_tokens, total_tokens, cached_tokens) from every LLM response
- [ ] **TOKN-03**: Processing time (wall-clock round-trip via time.monotonic()) recorded per LLM call
- [ ] **TOKN-04**: OpenRouter cost captured from response.usage.cost when available — gracefully absent when not
- [ ] **TOKN-05**: Temporal replay safety via deterministic SHA256 record IDs + UPSERT semantics
- [ ] **TOKN-06**: Token records included in nullify-then-recreate cycle (deleted on document reprocess)
- [ ] **TOKN-07**: Token data uses dedicated write path — NOT routed through ProcessingLogger (100-entry cap would silently drop data)

### Document Token Aggregation

- [ ] **AGGR-01**: Per-document token totals computed via SurrealQL math::sum() over llm_usage records
- [ ] **AGGR-02**: `GET /documents/{id}/tokens` endpoint returns per-document token aggregation
- [ ] **AGGR-03**: Token aggregates included in `GET /documents` list endpoint (batched, not N+1 per row)
- [ ] **AGGR-04**: Legacy documents (processed before v5.0) return zero/null tokens gracefully — no errors

### UI Display

- [ ] **UI-01**: Document list table shows aggregated token column with format: `[cached]/input/output`
- [ ] **UI-02**: Cost column shown when available (display as `$0.xxxx` with 4 decimal places)
- [ ] **UI-03**: Documents tab / detail shows per-LLM-call breakdown with timing, token counts, and cost

### No Regressions

- [ ] **NR-01**: All existing e2e integration tests continue to pass
- [ ] **NR-02**: E2E test verifies token counts are present and correct in llm_usage after document processing
- [ ] **NR-03**: E2E test verifies reprocessing a document produces identical token counts

## v5.x Requirements (Deferred)

Deferred to future releases within v5.x. Tracked but not in current roadmap.

- **TOKN-08**: Full pricing map for all OpenRouter models (env var JSON or API fetch) — defer until cost field is insufficient
- **TOKN-09**: Token usage budgets and threshold alerts — single-user tool doesn't need this yet
- **UI-04**: Cost charts or visualizations — vanilla JS SPA limitation; add if users request
- **AGGR-05**: Real-time token streaming during document processing — non-streaming pipeline doesn't benefit

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Prompt/response content storage in llm_usage | Too large; content stored separately in events/references |
| Cost estimation for models without cost reporting | Defer to v5.1 with pricing map |
| Token usage budgets / threshold alerts | Single-user research tool, not needed |
| Model-specific tokenizer implementations | OpenRouter reports usage; no need to count locally |
| Historical backfill for existing documents | Pipepline is replay-safe; backfill via reprocess, not migration |
