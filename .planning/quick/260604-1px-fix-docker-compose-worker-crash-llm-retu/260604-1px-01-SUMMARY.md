# Quick Task 260604-1px: Fix worker crash from invalid reference_type

**One-liner:** LLM was returning `reference_type="que_paso"` which violates the SurrealDB schema assertion (`espacio|tiempo|humanos|objetos`). Fixed the confusing prompt and added input validation.

## Root Cause

The `docker compose logs worker-1` showed:
```
RuntimeError: Found 'que_paso' for field `reference_type`, with record `reference:l11uonkw48t3at66kpng`, but field must conform to: $value = 'espacio' OR $value = 'tiempo' OR $value = 'humanos' OR $value = 'objetos'
```

Two contributing factors:
1. **Confusing prompt** (llm.py:521): `"Debes incluir al menos una referencia para que_paso (con reference_type 'humanos')."` — the LLM sometimes interpreted this as "set reference_type to 'que_paso'" because `que_paso` appears immediately before `reference_type` in the sentence.
2. **No input validation** (activities.py:1640): The activity passed whatever the LLM returned directly to the SurrealDB CREATE query with no validation.

## Fixes

### 1. Clarify LLM prompt (llm.py)
- Before: `"Debes incluir al menos una referencia para que_paso (con reference_type 'humanos').\n"`
- After: `"Incluye al menos una referencia que respalde el campo que_paso (usa reference_type 'humanos' para esa referencia).\n"`
- Rephrased to separate the field name from the reference_type instruction

### 2. Add reference_type validation (activities.py)
- Added validation block in `store_extraction_results_activity` before the CREATE query
- Invalid `reference_type` values are logged as warnings and skipped with `continue`
- Processing log receives a warning entry so the skip is visible in the UI
