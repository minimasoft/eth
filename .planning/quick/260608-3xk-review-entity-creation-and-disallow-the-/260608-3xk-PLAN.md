<objective>
**Prevent entities from being created without reference links — fix all creation codepaths with transactional guards, and fix delete_document to not leave orphan entities behind.**

**Purpose:** Audit found 38/38 entities in the DB have ZERO references (100% orphan rate). The root causes are: (1) `_dedup_and_link` creates entities before linking refs — if linking fails, orphan persists; (2) `store_extraction_results` creates place/person entities that only get reference links later via resolution — if resolution misses them, orphans persist; (3) `delete_document` doesn't collect entities linked via `event_participant` or `location_place_id`.

**Output:**
- DB with zero orphan entities (38 current orphans cleaned)
- Transactional guard in both `_dedup_and_link` implementations: if entity created but 0 refs linked → DELETE entity + log error
- Same guard in split endpoint
- `delete_document` collects entities from ALL link paths (reference, event_entity_link, event_participant, location_place_id)
</objective>

    **Problem:** In both `resolve_entities.py` and `resolve_entities_with_search.py`, the `_dedup_and_link` closure creates the entity FIRST, then tries to link references. If entity creation succeeds but ALL reference UPDATE calls fail (DB connection blip, constraint error, etc.), the entity exists with zero reference links — a permanent orphan.

    **Fix for resolve_entities.py `_dedup_and_link` (lines ~146-172) and resolve_entities_with_search.py `_dedup_and_link` (lines ~166-192):**

    After the `linked > 0` tracking loop, add a guard:

    ```python
    # After the for rid in ref_ids loop (lines ~165 in resolve_entities.py, ~185 in resolve_entities_with_search.py):
    
    # Guard: if we created this entity but linked ZERO references, roll back
    if created_id is not None and linked == 0:
        # Entity was inserted but no references point to it — delete it
        # to prevent orphan accumulation.
        activity.logger.error(
            "ENTITY ABORTED: created canonical_entity %s (%s, %s) but "
            "linked 0/%d references — rolling back. Ref IDs: %s",
            created_id, entity_name, entity_type, len(ref_ids),
            ref_ids,
        )
        try:
            await db_conn.execute(
                "DELETE FROM canonical_entity WHERE id = $1",
                created_id,
            )
        except Exception as del_exc:
            activity.logger.error(
                "Failed to delete aborted entity %s: %s",
                created_id, del_exc,
            )
        # Undo the total_created count since we deleted it
        nonlocal total_created
        total_created -= 1
        return 0  # No references linked
    ```

    **Implementation details:**
    - The guard runs after ALL ref-link attempts, checking `linked == 0` AND `created_id is not None`.
    - If triggered, DELETE the entity immediately (same connection, same transaction), log ERROR with entity details and ref_ids, and return 0.
    - Also decrement `total_created` via `nonlocal total_created`.
    - This is NOT a sub-transaction / savepoint (asyncpg savepoints add complexity). The entity exists briefly but is deleted in the same connection before any other reader sees it.

    **Fix for split_entity endpoint in entities.py (lines ~485-546):**

    Same pattern: after creating the new entity and updating references, verify at least one reference was linked. If not, delete the entity:

    ```python
    # After the reference update (around line 530 in entities.py)
    # Guard: verify at least one reference was linked to the new entity
    # (Reference count is implicit via the ref_placeholders UPDATE above;
    # if merged_ref_ids was non-empty but all UPDATEs failed silently,
    # the entity is orphaned.)
    if not merged_ref_ids:
        # No references to link — delete the just-created entity
        await db.execute(
            "DELETE FROM canonical_entity WHERE id = $1",
            new_entity_id,
        )
        logger.error(
            "ENTITY ABORTED: split created entity %s (%s) but had "
            "zero reference IDs to link — rolled back",
            new_entity_id, new_name,
        )
        raise HTTPException(
            status_code=500,
            detail=f"Split created entity '{new_name}' but no references to link.",
        )
    ```
    
    (This guard already partially exists — merged_ref_ids is checked earlier for emptiness. But add it as a final safety net.)
