# Quick Task 260905-55d: OpenStreetMap event map view + cheap geocoding

Goal: Add an additive **Mapa** tab to `index.html` rendering located events on OpenStreetMap
tiles (Leaflet 1.9.4 via CDN — matches the project's no-npm-build, one-file-UI pattern),
backed by a new `GET /geo/events` bbox geo-query endpoint, plus a **cheap geocoder**
(Nominatim public API, ≤1 req/s, DB-as-cache) exposed as a backfill CLI that fills
`event_location.lat/lon`.

**Ground truth verified during planning (2026-09-05):**
- Migration `0004_event_provenance_sources_geo.py` already added `event_location.lat/lon`
  (Float, nullable). Dev DB is at alembic head `0004`; 23 locations, 0 geocoded.
  **Do NOT create any new Alembic revision and do NOT touch 0004.**
- `api/models.py` already carries `lat`/`lon` on `EventLocationDetail` ("set by geocoding").
- Working tree currently has unrelated modified `.planning/` docs and one untracked dump —
  stage ONLY files listed below, never `git add -A` / `git add .`.
- API serves on host port **18001** (`/health` ok, `/ui/` 200). `./src` is volume-mounted
  into containers — code changes need only a container restart, no rebuild.
- Dev stack is running. Test runs go through `./test.sh` (isolated `eth-test` stack) —
  NEVER pytest/uv ad-hoc on the host (AGENTS.md).

**Geocoding approach decision (the "cheap" answer):** Nominatim public API
(`https://nominatim.openstreetmap.org/search`) — $0 cost, no API key, volume here is tens of
distinct place names (well within the published policy: max 1 req/s, descriptive User-Agent,
results cached). The DB is the cache: coords persist on `event_location` rows keyed by name,
so repeated backfills only pay for unlocated names. Self-hosting Nominatim or a static
lookup table is overkill at this scale. Degradation contract: any failure (network, empty
result, rate limit) leaves `lat/lon` NULL — those locations simply don't render on the map;
nothing else breaks. Approximation note: identical place names share coords
("Guadalajara" ambiguity) — acceptable per the request for approx coordinates; document in
the module docstring.

**Route-path decision:** use `GET /geo/events`, NOT `/events/geo` — FastAPI matches routes
in registration order, so `/events/{event_id}` in `events_v2.py` would shadow `/events/geo`
forever. `/geo/events` is immune to router ordering.

## Task 1 — Backend: `GET /geo/events` bbox endpoint + models + registration

**MAP-01**

1. **Models** (`api/models.py`) — append two pydantic models following the existing style
   (docstring on every field):
   - `GeoEventItem`: `event_id: str`, `title: str`, `time_start: str | None`,
     `time_end: str | None`, `time_precision: str | None`, `lat: float`, `lon: float`,
     `location_id: str`, `location_name: str`, `location_type: str | None`,
     `document_id: str | None`, `document_filename: str | None`.
   - `GeoEventsResponse`: `total: int`, `items: list[GeoEventItem]`.

2. **Router** (`api/routes/geo.py`) — follow `events_v2.py` patterns exactly
   (`APIRouter(tags=["Map"])`, `from eth_pipeline.db import get_db`, logger, parameterized
   `$N` asyncpg queries, `HTTPException(status_code=502, detail="Failed to query database.")`
   on DB failure):
   - `GET /geo/events` with `min_lon: float | None`, `min_lat: float | None`,
     `max_lon: float | None`, `max_lat: float | None` (`Query(None)`), and
     `limit: int = Query(500, ge=1, le=2000)`.
   - All-or-none bbox: if any of the four is provided, all four must be — else
     `HTTPException(400, "bbox requires min_lon, min_lat, max_lon, max_lat together")`.
     Ranges: lat ∈ [-90, 90], lon ∈ [-180, 180], min ≤ max — else 400.
   - SQL: `SELECT el.id, el.name, el.location_type, el.lat, el.lon, ev.id AS event_id,
     ev.title, ev.time_start, ev.time_end, ev.time_precision, d.id AS doc_id, d.filename`
     `FROM event_location el JOIN event_v2 ev ON ev.id = el.event_id`
     `LEFT JOIN document d ON d.id = ev.document_id`
     `WHERE el.lat IS NOT NULL AND el.lon IS NOT NULL` + optional
     `AND el.lat BETWEEN $n AND $n+1 AND el.lon BETWEEN $n+2 AND $n+3`
     `ORDER BY ev.time_start DESC NULLS LAST LIMIT $n`.
     All values parameterized — no f-string interpolation of user input.
   - Response: `GeoEventsResponse(total=len(items), items=[...])` (ISO-format datetimes
     like events_v2.py does).

3. **Registration** (`api/__init__.py`) — add
   `from eth_pipeline.api.routes.geo import router as geo_router  # noqa: E402` after the
   events_v2 import, and `app.include_router(geo_router)` after
   `app.include_router(events_v2_router)`. Two additive lines; touch nothing else.

4. **Tests** (`tests/test_geo_api.py`, integration — they use `db_connection`, so conftest
   auto-marks them): follow the mimic-the-SQL pattern of `tests/test_event_api.py`
   (existing suite does not exercise routes over HTTP; don't introduce TestClient here).
   - Fixture usage: `v7_test_event` seeds location `test-events-v7-loc-001`
     ("Ciudad de México", no coords). In tests, `UPDATE event_location SET lat = 19.4326,
     lon = -99.1332 WHERE id = 'test-events-v7-loc-001'` (teardown deletes the row).
   - `test_bbox_filters_outside`: point inside bbox appears in the mimicked result query;
     bbox over Europe excludes it.
   - `test_null_coords_excluded`: location with NULL lat/lon never matches the geo query
     (add a second unlocated location row inside the bbox; assert absent).
   - `test_limit_respected`: LIMIT clause caps rows.
   - `test_parse_bbox_validation`: unit-style — import `parse_bbox` from the route module
     (see below) and assert: all four present + valid → tuple; missing one → raises;
     min>max → raises; lat 95 → raises; lon 200 → raises.
   - Implementation note for testability: put bbox parsing/validation in a pure function
     `parse_bbox(min_lon, min_lat, max_lon, max_lat) -> tuple[float, float, float, float]`
     in `geo.py` that raises `ValueError` with the message above; the route handler catches
     `ValueError` → `HTTPException(400, str(exc))`. This keeps validation unit-testable
     without DB or HTTP.

## Task 2 — Geocoder: Nominatim client + backfill CLI

Files: `src/eth_pipeline/geo/__init__.py` (new), `src/eth_pipeline/geo/geocode.py` (new),
`tests/test_geocode.py` (new)

**MAP-02**

1. `src/eth_pipeline/geo/__init__.py` — minimal: docstring + `from eth_pipeline.geo.geocode
   import backfill, geocode_place` (noqa: F401 re-export).

2. `src/eth_pipeline/geo/geocode.py` — module docstring MUST document: Nominatim public API
   usage policy compliance (≤1 req/s via `rate_seconds=1.1` sleep, descriptive User-Agent,
   results persisted in `event_location` as the cache, no bulk geocoding), zero monetary
   cost, self-hosted Nominatim as the escalation path for heavier volume, and the
   same-name→same-coords approximation. Implementation:
   - `NOMINATIM_URL = "https://nominatim.openstreetmap.org/search"`; params
     `{"q": name, "format": "json", "limit": 1}` (URL-encoded via httpx params — never
     string-concatenate the user-controlled name into the URL).
   - Headers: `{"User-Agent": "eth-pipeline/1.0 (event map geocoding)"}` — required by
     Nominatim policy; timeout 10s; use `httpx.Client` (httpx ≥0.28 already in pyproject —
     no new dependency).
   - `geocode_place(name: str, *, client: httpx.Client | None = None) -> tuple[float, float] | None`:
     GET; on non-2xx, empty result list, network error, or malformed payload → log and
     return `None` (never raise). On success return `(float(lat), float(lon))`. Accept an
     injected client so tests can pass an `httpx.MockTransport` client (zero network in
     tests).
   - `backfill(conn: asyncpg.Connection, *, limit: int = 100, rate_seconds: float = 1.1,
     geocoder=geocode_place) -> int`:
     - `SELECT DISTINCT name FROM event_location WHERE lat IS NULL AND name <> '' LIMIT $1`.
     - For each name: `coords = geocoder(name)`; if found →
       `UPDATE event_location SET lat = $2, lon = $3 WHERE name = $1 AND lat IS NULL`
       (updates every row sharing the name — the name-keyed cache); sleep
       `rate_seconds` between requests regardless of success (policy compliance).
     - Return the number of names successfully geocoded. `geocoder` is injectable for
       tests (monkeypatched, no network).
   - CLI `if __name__ == "__main__":` — argparse `--limit` (default 100) and `--rate`
     (default 1.1); async main resolving the DSN the same way the rest of the app does
     (reuse `eth_pipeline.db.get_db` context manager); log a final summary line
     "Geocoded N place names". Run inside the container (AGENTS.md pattern):
     `docker compose run --rm api uv run python -m eth_pipeline.geo.geocode --limit 50`.

3. `tests/test_geocode.py`:
   - Unit (auto-marked: no stateful fixtures): Nominatim JSON payload → coords via
     `httpx.MockTransport`; empty `[]` → None; HTTP 500 → None; transport error → None.
   - Integration (uses `db_connection`): insert an `event_location` row with NULL lat
     (unique id, own cleanup, or reuse `v7_test_event`'s unlocated row and clean the
     UPDATE in a finally), run `backfill(conn, geocoder=lambda name: (19.4326, -99.1332))`,
     assert the row's lat/lon were written; with `geocoder=lambda name: None`, assert the
     row stays NULL and no exception escapes.
