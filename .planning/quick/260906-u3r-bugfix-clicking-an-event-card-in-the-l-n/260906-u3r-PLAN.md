<objective>
Fix the user-reported regression: clicking an event card in the Línea de tiempo "loads the event but never shows it" (no split view, stale logic routes the detail into the hidden Eventos tab).

Root cause (verified empirically with a driven browser): the dev stack serves a STALE docker image. The api container ships index.html and linea-tiempo.js from commit c44abee (quick task 260906-s7d — BEFORE 260906-t6c). In that served version, the linea-tiempo.js card click handler calls `showEventDetail(id)`, which renders `#event-detail-panel` inside the hidden `#tab-eventos` section while the user stays on `#tab-lineatiempo` — exactly the reported symptom ("event is being loaded but not switching to events tab"). The t6c fix (commit cbaac66/2868559: `toggleEventDetailFromTimeline` → `openEventDetail(id, 'lineatiempo')` → `#lineatiempo-split.split-open`) exists in the working tree but was never deployed because the image was never rebuilt.

Incidental finding during root-cause investigation (fixed here because it is accidentally mis-nested code in the same file): commit e4db2f5 (260906-l1o) inserted the `#logout-btn` click wiring and an `applyPasscodeVisibility()` call INSIDE `ensurePasscode()`'s `if (await checkPasscode(...))` block (index.html ~lines 4125–4147). Consequence: when passcodes are already stored, `ensurePasscode` returns early and the logout button gets NO listener — "Cerrar sesión" silently does nothing for returning users. This task re-nests the wiring at top level.

Purpose: make the deployed UI match the working tree so the t6c split-view behavior actually reaches the user, and remove the mis-nested dead-wiring accident while it is fresh.
Output: rebuilt dev stack serving HEAD static assets; browser-verified split open/close flows; re-nested logout wiring with a static guard test.
</objective>
