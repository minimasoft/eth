# Quick Task 260602-j53: Fix cascade delete in m002 test cleanup

## Task 1: Add cascading cleanup for events and references in `cleanupTestData`

**Problem:** `cleanupTestData()` in `pipeline_m002.test.ts` deletes test documents via raw SQL (`DELETE document:${docId};`), but does not first delete the events and references linked to those documents. This leaves orphaned records in the database.

**Fix:** Before deleting each test document, cascade delete references, events, and document_chunks for that document — matching the cascade logic in the `delete_document` API endpoint.

### Files
- `tests/integration/pipeline_m002.test.ts` — the `cleanupTestData()` function

### Action
1. For each `docId` in `testDocIds`, emit SQL in this order before `DELETE document:${docId}`:
   - `DELETE document_chunk WHERE document = document:${docId};`
   - `DELETE reference WHERE event IN (SELECT id FROM event WHERE document = document:${docId});`
   - `DELETE event WHERE document = document:${docId};`

### Verify
- The cleanup function produces no errors when running against documents that have events, references, and chunks.
- Order is correct: references first (they depend on events), then events, then document_chunks, then the document itself.

### Done
- `cleanupTestData()` in `pipeline_m002.test.ts` cascades deletes before removing each test document.
