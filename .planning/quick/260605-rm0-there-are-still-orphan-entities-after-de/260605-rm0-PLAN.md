Since the links are already gone, Step 8b's query `SELECT entity FROM event_entity_link WHERE event IN (...)` returns nothing, and orphan cleanup is a no-op.

    1. **Before Step 1b** (before the event_entity_link DELETE), insert a collection block:
       ```python
       # --- Step 1a: Collect non-event entities linked via event_entity_link ---
       # Collect BEFORE Step 1b deletes the edges, so we know which entities
       # to check for orphan status after references are deleted.
       eel_entity_rows = await conn.fetch(
           "SELECT entity FROM event_entity_link "
           "WHERE event IN ("
           "  SELECT id FROM canonical_entity "
           "  WHERE entity_type = 'event' AND properties->>'document_id' = $1"
           ")",
           document_id,
       )
       eel_entity_ids = list({
           str(r["entity"]) for r in eel_entity_rows
           if r["entity"] is not None
       })
       ```
    2. **Keep Step 1b** (DELETE FROM event_entity_link) in its current location — it correctly deletes edges for events in this doc.
    3. **Replace the current Step 8b** with code that uses the pre-collected `eel_entity_ids` (saved from Step 1a) instead of re-querying the already-deleted links:
       - Deduplicate against `affected_ce_ids` (entities already handled by Step 8)
       - For each remaining entity, check `ref_remaining == 0 AND eel_remaining == 0` (same logic as current Step 8b)
       - The `eel_remaining` check is correct here because it counts ALL event_entity_link edges — if this entity is linked by other documents' events, `eel_remaining > 0` and we don't delete it
       - Delete if both counts are zero

    Keep the current flow for `affected_ce_ids` (Steps 2-8) unchanged — that path works correctly for entities discovered via `reference.canonical_entity`/`reference.entity_id`.

<task type="auto">
  <name>Task 2: Fix list_entities reference_count to include entity_id column</name>
  <files>
    src/eth_pipeline/api/routes/entities.py
  </files>
  <action>
    **Bug:** The `list_entities` endpoint computes `reference_count` by querying only `reference.canonical_entity`. It misses entities whose references were set via `reference.entity_id` (Phase 17 search-first resolution populates `entity_id` rather than `canonical_entity`). This means the displayed count can be 0 even when references exist, and it also means the e2e test cannot rely on `reference_count` to detect orphan entities.

    **Fix:** Replace the single-column COUNT with a dual-column COUNT at `entities.py` lines ~96-104:

    Current SQL (bad):
    ```sql
    SELECT canonical_entity AS canonical_entity_id, COUNT(*) AS cnt FROM reference
    WHERE canonical_entity IN ({placeholders})
    GROUP BY canonical_entity
    ```

    New SQL (good — uses UNION ALL to count both FK columns):
    ```sql
    SELECT entity_id, SUM(cnt) AS cnt FROM (
      SELECT canonical_entity AS entity_id, COUNT(*) AS cnt FROM reference
      WHERE canonical_entity IN ({placeholders})
      GROUP BY canonical_entity
      UNION ALL
      SELECT entity_id AS entity_id, COUNT(*) AS cnt FROM reference
      WHERE entity_id IN ({placeholders2})
      AND entity_id IS NOT NULL
      AND (canonical_entity IS NULL OR canonical_entity NOT IN ({placeholders3}))
      GROUP BY entity_id
    ) AS combined GROUP BY entity_id
    ```
    
    Simpler approach (preferred — keeps executor code clean): Build two separate queries, run both, merge results into `ref_counts` dict. This avoids complex UNION logic:

    1. Run the existing query (count by `canonical_entity`) — same as before
    2. Run a second query: count by `entity_id` for the same entity IDs
    3. Merge: `ref_counts[eid] = ref_counts.get(eid, 0) + entity_id_count`

    This way `reference_count` reflects ALL references pointing to the entity, regardless of which FK column was populated.
  </action>
