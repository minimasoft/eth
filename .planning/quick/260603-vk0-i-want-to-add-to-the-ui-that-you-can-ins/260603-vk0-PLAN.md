## PLAN: Add document log inspection UI

**Mode:** quick
**Description:** Add a Logs tab to the UI that allows users to inspect processing logs for a document, with auto-refresh when the view is active.

### Task 1: Add Logs tab with log viewer UI

**Files:**
- `src/eth_pipeline/static/index.html`

**Action:**
1. Add "Logs" button to nav bar (after References)
2. Add "View Logs" button to each document row's Actions column (alongside delete)
3. Add log viewer HTML section (tab content) with:
   - Document info header showing current document ID and filename
   - Log table: created_at, severity (color-coded badge), step_name, message, details (expandable)
   - Pagination controls (50 per page)
   - Loading/empty/error states
4. Add JavaScript for:
   - `fetchLogs(documentId, page)` — calls `GET /documents/{documentId}/logs?page=N`
   - `renderLogs(data)` — renders the log entries table
   - Severity badges: info=blue, warning=yellow/amber, error=red
   - Pagination handlers
   - Auto-polling: when viewing logs for a document that is still processing, poll every 5s
   - Stop polling when tab switches away (cleanup timers in switchTab)
   - Expandable details JSON viewer
5. Wire up "View Logs" button click to switch to Logs tab and load logs
6. Wire up document info in log view header (back button to return to documents)

**Verify:**
- Logs tab renders with loading/empty/data states
- Log entries show severity with correct colors
- Pagination works
- Auto-polling starts/ stops correctly
- "View Logs" button in documents table navigates to logs tab

**Done:** When log viewer is functional with all states, pagination, and auto-refresh.
