    Create `scripts/cleanup_orphan_references.py` — a standalone async CLI script that:

    1. **Imports & setup:**
       - Imports `get_db` from `eth_pipeline.db` (the standard async WebSocket connection)
       - Uses `asyncio.run()` to call an async `main()` (get_db is async — cannot use synchronous HTTP like init_schema.py)
       - Uses `argparse` for CLI, matching init_schema.py's conventions (env var fallbacks, --help)

    2. **CLI args (argparse):**
       - `--url`: SurrealDB WebSocket URL (env: `SURREAL_URL`, default: `ws://localhost:8000/rpc`)
       - `--user`: (env: `SURREAL_USER`, default: `root`)
       - `--password`: (env: `SURREAL_PASS`, default: `root`)
       - `--ns`: (env: `SURREAL_NS`, default: `eth`)
       - `--db`: (env: `SURREAL_DB`, default: `pipeline`)
       - `--execute`: flag to actually DELETE orphans (default: dry-run, only report)
       - `--orphan-events`: flag to also find/delete orphan events (events whose document is gone)
       - `--verbose` / `-v`: flag to show full record details (default: summary counts only)

    3. **Async detection logic (three queries):**

       After connecting via `async with get_db(...) as db:`:

       **Orphan Type A** — reference.event links to a nonexistent event:
       ```sql
       SELECT id, verbatim_text, event
       FROM reference
       WHERE event NOT IN (SELECT id FROM event)
       ```

       **Orphan Type B** — reference points to an event whose document is gone:
       ```sql
       SELECT id, verbatim_text, event
       FROM reference
       WHERE event IN (
         SELECT id FROM event
         WHERE document NOT IN (SELECT id FROM document)
       )
       ```

       **Orphan Type C** (only if `--orphan-events` is passed) — events with no document:
       ```sql
       SELECT id, que_paso
       FROM event
       WHERE document NOT IN (SELECT id FROM document)
       ```

    4. **Reporting format:**
       - Print a summary table showing counts per orphan type
       - If `--verbose`, print the full list of orphan record IDs and key fields
       - Print a total orphan count line

    5. **Delete logic (only if `--execute`):**
       - For Type A: `DELETE reference WHERE event NOT IN (SELECT id FROM event)`
       - For Type B: `DELETE reference WHERE event IN (SELECT id FROM event WHERE document NOT IN (SELECT id FROM document))`
       - For Type C (if `--orphan-events`): `DELETE event WHERE document NOT IN (SELECT id FROM document)`
       - Print confirmation of how many records were deleted per type
       - Do NOT use `RETURN BEFORE` or count tricks — just execute DELETE and trust SurrealDB's response

    6. **Error handling:**
       - Catch `ConnectionError` from get_db and print a clear "SurrealDB not reachable" message — exit 1
       - Catch `Exception` generically, print error + traceback, exit 1
       - Use `try/finally` to ensure connection is closed (get_db context manager handles this automatically)

    7. **Invocation pattern** (matching init_schema.py):
       ```
       uv run python scripts/cleanup_orphan_references.py
       uv run python scripts/cleanup_orphan_references.py --execute
       uv run python scripts/cleanup_orphan_references.py --orphan-events --execute -v
       ```

    8. **Use `sys.stdout` for output**, `sys.stderr` for errors, consistent with init_schema.py style.

    Important implementation details:
    - The script MUST use `asyncio.run(main())` pattern because `get_db()` is async WebSocket-based (`AsyncWsSurrealConnection`)
    - Default to DRY-RUN. `--execute` is required to actually delete anything
    - Report counts clearly: "Orphan Type A (event missing): N records" etc.
    - If verbose mode, print each orphan record's id, verbatim_text, and event for inspection
    - Ensure the epilog in argparse mentions all env var overrides per init_schema.py convention
